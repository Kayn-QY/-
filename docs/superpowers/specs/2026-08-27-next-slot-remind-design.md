# 排班提醒统一「下一场 + X分钟后开播/换播/下播」设计文档

日期：2026-08-27
状态：已批准，实施中

## 背景

用户希望排班提醒内容统一为「第N场 时间段 主播（或无场次），X分钟后 开播/换播/下播」的格式，且提醒对象永远指向**下一场**（前方最近一场），而非正在直播的当前场。倒计时 X = 下一场开始时间 − 当前北京时间。

## 核心规则

| 当前状态 | 下一场 | 动作 | 主播位 |
|---|---|---|---|
| 正在直播 | 有人 | 换播 | 主播名 |
| 正在直播 | 无人（保留时间段） | 下播 | 无场次 |
| 空闲 | 有人 | 开播 | 主播名 |

- X < 1 分钟 → 文案「即将开播/换播/下播」（沿用现有）
- X ≥ 60 分钟 → 自动转「X小时后」（沿用现有倒计时函数）
- 空闲且下一场 slot 也无人 → 继续向后找最近一场有人场次 → 「X分钟后开播」（沿用现有 nextRemind 逻辑）

## 改动范围

### 1. 网页 `render_web.py`

两处同步改造（前端实时 JS `buildRemind` + 服务端预渲染 `build_remind_html`）：
- 直播中分支：显示对象从「当前场」改为「下一场」（第N场 / 时间段 / 主播），动作按下一场是否有人判「换播 / 下播」
- 无人场主播位占位文案：「无人播」→「无场次」
- 下播档无下一场数据时：slot 显示「第N场」（下一场槽名，无下一场则用当前场名），主播位「无场次」，X 基准 = 当前场结束时间

### 2. 桌面卡片 `main.js`

- `computeOutput` live 分支：与网页一致改为显示下一场 / 无场次 + 下播
- `collectEvents`（语音合并组句 + 系统通知）：live 分支事件指向下一场（slot / hhmm / anchor），语音文案统一为「第N场 时间段 主播，还有N分钟换播/下播」；空闲分支为「…还有N分钟开播」
- 保持 10 / 5 两档触发

### 3. 后台 `reminder.py`

- 触发事件从「仅开播」扩展为**开播 / 换播 / 下播**三类
  - 开播事件：每场 anchor 非空，at = 场次开始
  - 切换事件（换播/下播）：每场 anchor 非空，at = 场次结束；下一场（SLOT_ORDER 下一槽）有人 → 换播，否则 → 下播
- 每类事件在**提前 10 分钟、5 分钟各触发一次**通知（LEADS = [10, 5]）
- 文案改为「N分钟后开播/换播/下播」（N = 10 或 5），title 带事件类型与直播间
- state 去重 key 需含 lead 维度，避免两档互相覆盖

## 验证

- 三处逻辑输出对齐（同一时刻同一 next 场次 / 动作 / X）
- `reminder.py --once` 实测弹窗文案
- 重新渲染推送网页，重启桌面卡片
